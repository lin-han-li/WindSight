# 万物数驱：终端数据上传协议（当前无认证模式）

本文给终端、网关、PLC、LoRa 采集程序和第三方业务系统使用，说明从注册数据源到成功上传并看到曲线的完整方式。

> 当前服务器的“上传认证校验”已关闭。终端上传**不需要** `node_key`、`key_id`、`secret`、HMAC 或任何 `X-WindSight-*` 认证头；仍需先在页面注册数据源，且上传中的来源 ID 必须等于已注册节点 ID。

## 1. 最短成功流程

```text
注册数据源一次 → JSON 中使用同一 device_id → POST /api/upload → status: success → 实时数据台选择字段
```

当前部署接口：

```text
POST http://8.163.62.41/api/upload
Content-Type: application/json
```

## 2. 上传前：注册数据源

1. 登录 `http://8.163.62.41/login`。
2. 管理员可从左侧 **注册我的数据源** 进入，或直接打开 `http://8.163.62.41/my/tree`。
3. 填写节点 ID 和显示名称，点击 **注册节点**。
4. 之后同一设备每次上传都使用该 ID；新增设备才注册新的节点。

### 节点 ID 规则

| 项目 | 要求 | 示例 |
| --- | --- | --- |
| 长度 | 3～64 个字符 | `ENV_ROOM_A01` |
| 字符 | `A-Z`、`0-9`、`_`、`-` | `LORA-NODE-01` |
| 唯一性 | 全平台唯一 | 不可重复注册 |
| 建议 | 全大写 | `WATER_METER_01` |

## 3. HTTP 请求规范

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 方法 | `POST` | 固定 |
| 地址 | `<平台地址>/api/upload` | 当前为 `http://8.163.62.41/api/upload` |
| `Content-Type` | `application/json` | 固定 |
| 字符编码 | UTF-8 | 推荐 |
| 请求体 | JSON 对象 | 顶层不能是数组、文本或单个数字 |
| 认证头 | 不需要 | 当前服务器已关闭上传认证校验 |

建议一帧上传一台设备在一个时刻的完整状态。单帧应明显小于 2 MB。

## 4. 推荐 JSON 外壳与每个参数

```json
{
  "device_id": "ENV_ROOM_A01",
  "reported_at": "2026-09-06T10:30:00+08:00",
  "telemetry_schema": {},
  "metrics": {},
  "status": {},
  "tags": {}
}
```

| 字段 | 必填 | 类型 | 示例 | 作用 |
| --- | --- | --- | --- | --- |
| `device_id` | 三选一必填 | 字符串 | `"ENV_ROOM_A01"` | 推荐来源标识；等于注册节点 ID。 |
| `node_id` | 三选一必填 | 字符串 | `"ENV_ROOM_A01"` | 可替代 `device_id`。 |
| `source_id` | 三选一必填 | 字符串 | `"ENV_ROOM_A01"` | 可替代 `device_id`。 |
| `reported_at` | 否 | ISO 8601 字符串 | `"2026-09-06T10:30:00+08:00"` | 终端采集时间，作为原始 JSON 保存。 |
| `telemetry_schema` | 强烈建议 | 对象 | 见第 6 节 | 定义中文名称、单位和业务语义。 |
| `metrics` | 建议 | 对象 | `{"temperature_c":25.6}` | 推荐集中存放要画曲线的数值。 |
| `status` | 否 | 对象或字符串 | `{"online":true}` | 运行状态；布尔/文本不画曲线。 |
| `tags` | 否 | 对象 | `{"site":"实验室A"}` | 位置、型号等静态辅助信息。 |
| 其他字段 | 否 | 任意 JSON 值 | `gateway`、`alarm`、`channels` | 完整保存；其中有限数值会自动成为曲线字段。 |

### 来源标识选择规则

平台按下面顺序选择来源：

```text
node_id → device_id → source_id
```

推荐每帧只放一个 `device_id`。如果同时放多个来源字段，平台选择优先级最高的那个；不要让它们取不同值。

### 时间规则

- 曲线横轴、实时顺序和历史检索使用**服务器收到请求的时间**；
- `reported_at` 是终端采集时间，仅保存在原始 JSON；
- 不要把采集时间写成数值时间戳，例如 `1725589800`，它会被当作普通数值曲线字段；推荐 ISO 8601 字符串。

## 5. 数据类型、字段路径与通道数

### 什么会形成曲线

| JSON 值 | 是否形成曲线 | 处理方式 |
| --- | --- | --- |
| 有限数字，如 `25.6`、`0`、`-12.3` | 是 | 自动保存为可选字段。 |
| 对象 | 视内部字段 | 递归展开内部数值。 |
| 数组 | 视内部元素 | 数值元素按下标形成字段。 |
| 字符串、布尔值、`null` | 否 | 保留在原始 JSON。 |
| `NaN`、`Infinity` | 否 | 不应发送，不是标准 JSON 数值。 |

> 平台扫描整个 JSON。来源 ID 和 `telemetry_schema` 请使用字符串；不要在 schema 中写数值备注，否则这些数值也会成为曲线候选字段。

### 字段路径示例

| JSON 片段 | 页面字段路径 |
| --- | --- |
| `{"metrics":{"temperature_c":25.6}}` | `metrics.temperature_c` |
| `{"power":{"voltage_v":220.1}}` | `power.voltage_v` |
| `{"channels":[12.1,11.9]}` | `channels[0]`、`channels[1]` |
| `{"sensors":[{"value":1.2},{"value":1.5}]}` | `sensors[0].value`、`sensors[1].value` |

建议使用英文、数字、下划线组成字段键，例如 `temperature_c`、`power_kw`、`ch_01`。若键名包含点号、方括号、逗号或反斜杠，平台会转义路径，schema 更难维护。

### 通道数量由终端决定

```json
{
  "device_id": "DAQ_001",
  "metrics": {
    "ch_01": 12.34,
    "ch_02": 10.98,
    "ch_03": 0.44,
    "ch_04": 8.12,
    "ch_05": 7.91
  }
}
```

通道可为 1、4、32 或更多。新数值字段会自动出现。实时页可勾选任意数量字段，但曲线区同时展示前 4 项；总通道数不受限制。

## 6. telemetry_schema：字段名称、单位和语义

`telemetry_schema` 不传测量值，只定义显示方式；它的键必须与真实数值的字段路径完全一致。

```json
"telemetry_schema": {
  "metrics.temperature_c": {
    "label": "环境温度",
    "unit": "℃",
    "semantic": "temperature"
  }
}
```

| 参数 | 必填 | 类型 | 示例 | 说明 |
| --- | --- | --- | --- | --- |
| 路径键 | 是 | 字符串 | `metrics.temperature_c` | 对应真实数值字段路径。 |
| `label` | 否 | 字符串 | `环境温度` | 页面显示名；缺省时显示路径。 |
| `unit` | 否 | 字符串 | `℃`、`kPa`、`V` | 页面单位，不转换数值。 |
| `semantic` | 否 | 字符串 | `temperature`、`pressure` | 业务语义。 |

规则：

1. schema-only 字段没有真实数值时不会出现在字段列表；
2. 平台读取该数据源**最新一帧**的 schema；
3. 建议每一帧发送完整 schema，否则名称、单位和语义可能回退为字段路径；
4. `label`、`unit`、`semantic` 用字符串，避免无关数值字段。

### 7.6 LoRa 网关：一个终端一帧

一个网关收到多台 LoRa 终端时，每台终端应单独注册、单独发送一帧。网关信息作为普通字段一起保存：

```json
{
  "device_id": "LORA_ENV_001",
  "reported_at": "2026-09-06T10:34:00+08:00",
  "telemetry_schema": {
    "metrics.temperature_c": {"label":"温度","unit":"℃","semantic":"temperature"},
    "metrics.humidity_rh": {"label":"湿度","unit":"%RH","semantic":"humidity"},
    "gateway.rssi_dbm": {"label":"接收信号强度","unit":"dBm","semantic":"rssi"},
    "gateway.snr_db": {"label":"信噪比","unit":"dB","semantic":"snr"}
  },
  "metrics": {"temperature_c": 24.7, "humidity_rh": 55.6},
  "gateway": {"gateway_id":"GW_9704", "rssi_dbm":-83, "snr_db":8.5, "frequency_mhz":470.3},
  "lora": {"fport":2, "fcnt":186}
}
```

如果网关收到 `LORA_ENV_001` 与 `LORA_WATER_002`，应发送两次请求，而不是把它们塞进同一个数组后只使用网关 ID。

## 8. PowerShell：无认证直接上传

1. 将任一模板保存为 `payload.json`。
2. 修改其中的 `device_id` 为已注册节点 ID。
3. 在该文件所在目录运行：

```powershell
$base = "http://8.163.62.41"

curl.exe -X POST "$base/api/upload" `
  -H "Content-Type: application/json; charset=utf-8" `
  --data-binary "@.\payload.json"
```

或使用 PowerShell 原生命令：

```powershell
$base = "http://8.163.62.41"
$body = Get-Content -Raw -Encoding utf8 ".\payload.json"

Invoke-RestMethod `
  -Method Post `
  -Uri "$base/api/upload" `
  -ContentType "application/json; charset=utf-8" `
  -Body $body
```

当前不需要添加任何节点密钥或 HMAC 请求头。

## 9. 成功响应：每个参数的含义

```json
{
  "status": "success",
  "record_id": 42,
  "telemetry_id": 42,
  "source": {"field":"device_id", "id":"ENV_ROOM_A01"},
  "metric_count": 4,
  "auth": {"version":"node-id-only"},
  "device_config": {"upload_interval_seconds":60}
}
```

| 响应字段 | 含义 |
| --- | --- |
| `status` | `success` 表示本帧已入库。 |
| `record_id` / `telemetry_id` | 本帧的记录编号。 |
| `source.field` | 实际使用的来源字段。 |
| `source.id` | 上传的来源原始值。 |
| `metric_count` | 本帧识别出的有限数值字段数量。 |
| `auth.version` | 当前无认证模式下为 `node-id-only`。 |
| `device_config.upload_interval_seconds` | 平台建议的上传周期，单位秒。 |

## 10. 上传后在页面确认

### 实时数据台

1. 打开 `<平台地址>/monitor`。
2. 点击刷新数据源，选择刚上传的节点。
3. 勾选数值字段。
4. 查看最新值、字段曲线、原始 JSON 和最近记录。

### 历史回放

1. 打开 `<平台地址>/overview`。
2. 选择数据源和字段。
3. 选择“近 5 分钟”或清空时间范围。
4. 点击 **查询历史**。

历史查询依据服务器接收时间。

## 11. 常见问题

| 现象 / 返回 | 原因 | 处理 |
| --- | --- | --- |
| `status: success` 且 `metric_count > 0` | 数据成功入库 | 选择数据源和字段即可。 |
| `status: success` 但 `metric_count: 0` | 没有有限数值字段 | 在 `metrics` 中加入数字。 |
| `node_not_registered` | ID 未注册或不一致 | 先在 `/my/tree` 注册并核对 ID。 |
| `source_identifier_invalid` | ID 格式错误 | 使用 3～64 位 `A-Z`、数字、`_`、`-`。 |
| `telemetry_invalid` | 顶层不是对象或缺少来源字段 | 使用 `{}` 顶层并加入 `device_id`。 |
| 数据源下拉为空 | 只注册了节点，未成功上传通用 JSON | 确认响应为 `success`，刷新数据源。 |
| 有记录但无可选字段 | 没有数值字段 | 检查 `metric_count`。 |
| 名称或单位显示字段路径 | schema 路径不对应真实路径，或最新帧未带 schema | 对照第 5 节路径，每帧发送完整 schema。 |
| 曲线没有刚上传数据 | 未选择字段，或历史范围不含服务器接收时间 | 勾选字段，选择“近 5 分钟”。 |
| 数据进入旧风机记录 | JSON 同时存在 `sub` 和纯三位数字键，例如 `001`、`002` | 通用数据用 `metrics`、`channels` 等结构，不要使用旧风机帧形状。 |

## 12. 最终检查清单

- [ ] 已注册节点；
- [ ] `device_id` 与注册 ID 相同；
- [ ] `POST /api/upload`；
- [ ] 顶层为 JSON 对象；
- [ ] 当前无认证模式下未添加密钥或 HMAC 头；
- [ ] 至少一个有限数值字段；
- [ ] schema 路径与真实字段路径一致；
- [ ] 响应为 `status: success`；
- [ ] 实时和历史页面均能找到数据。
