# 万物数驱操作文档

本文面向平台管理员、设备接入人员和终端开发人员，说明从登录、注册数据源、获取凭据、上传任意 JSON，到查看实时与历史曲线的完整操作流程。

## 1. 平台用途与访问地址

万物数驱以“**一个已注册数据源对应一台设备、一个网关或一个业务来源**”为管理单位。上传端可以自行决定数据字段数量、嵌套结构、显示名称、语义和单位。

| 场景 | 地址 |
| --- | --- |
| 当前部署实例 | `http://8.163.62.41` |
| 本地运行默认地址 | `http://127.0.0.1:8080` |

以下示例统一以 `<平台地址>` 表示实际访问地址。登录账号由平台管理员分配；不要把账号密码、节点密钥或 HMAC `secret` 写入公开仓库、截图或日志。

---

## 2. 一次完整接入的流程

```text
登录平台
  → 注册数据源（仅首次）
  → 保存节点认证凭据
  → 终端持续 POST /api/upload 上报 JSON
  → 实时数据台查看最新值与曲线
  → 历史回放按时间范围查询记录
```

同一设备首次注册后不必重复注册。只有新增设备、遗失凭据或需要撤销旧凭据时，才需要重新操作数据源管理。

## 3. 登录与页面入口

1. 在浏览器打开 `<平台地址>/login`。
2. 输入分配的用户名、密码和页面验证码。
3. 管理员账号请选择 **管理员** 身份；普通账号请选择 **用户** 身份。
4. 登录后使用左侧导航进入以下页面：

| 页面 | 用途 |
| --- | --- |
| **我的数据源**（`/my/tree`） | 注册数据源、查看和重置节点认证凭据、设置上传周期。 |
| **实时数据台**（`/monitor`） | 选择来源和数值字段，查看最新值、实时曲线与原始 JSON。 |
| **历史回放**（`/overview`） | 按来源、字段、时间范围和记录数检索历史曲线。 |
| **系统设置**（`/settings`，管理员） | 设置节点离线时间、上传认证开关和前端轮询参数。 |

---

## 4. 注册数据源

### 4.1 页面操作

1. 打开 **我的数据源**。
2. 在顶部“注册节点”区域填写：
   - **节点 ID**：设备的稳定唯一标识；
   - **显示名称**：页面上的中文或业务名称，可留空。
3. 点击 **注册节点**。
4. 页面会显示认证配置。立即复制并保存到终端设备的私有配置中。
5. 在左侧节点树选择新节点，可按需设置“上传周期”。允许范围为 **5～86400 秒**。

### 4.2 节点 ID 规则

- 长度：3～64 个字符；
- 允许：大写字母 `A-Z`、数字 `0-9`、下划线 `_`、短横线 `-`；
- 推荐形式：`LAB_SENSOR_01`、`LORA_GATEWAY_01`、`WATER_METER_A01`；
- 平台会将上传时的来源 ID 统一转换为大写；终端侧建议从一开始就使用大写，避免混淆；
- 一个节点 ID 全平台唯一，不能被重复注册。

### 4.3 注册后得到的凭据

每个节点会生成两种上传凭据：

| 凭据 | 用途 | 推荐场景 |
| --- | --- | --- |
| `node_key` | HTTP 请求头 `X-WindSight-Node-Key` | 联调、演示、脚本验证。 |
| `key_id` + `secret` | HMAC-SHA256 请求签名 | 长期运行的网关、传感器终端和生产环境。 |

首次注册或点击“重置签名凭证”时，务必保存 `secret`。重置时可以选择保留旧 HMAC 凭据 24 小时作为过渡，也可以立即使旧凭据失效。

## 5. 通用 JSON 数据规则

### 5.1 接口

```text
POST <平台地址>/api/upload
Content-Type: application/json
```

请求体顶层必须是 JSON 对象，并包含以下来源标识中的至少一个：

1. `node_id`
2. `device_id`
3. `source_id`

若同时存在多个来源标识，平台按上面的顺序选择。因此一帧数据中应只保留一个来源标识，或确保它们完全一致。

### 5.2 哪些字段会形成曲线

- **有限数值**：自动保存为可选字段，能在实时数据台和历史回放中绘制曲线；
- **对象和数组**：递归展开为路径，例如 `environment.temperature`、`channels[0]`；
- **文本、布尔值、`null`**：保留在原始 JSON 中，但不参与曲线；
- 原始 JSON 会完整保存，便于回溯终端实际发送的内容。

### 5.3 字段名称、单位和语义

使用顶层 `telemetry_schema` 为字段指定页面显示信息。键必须与数值字段的展开路径一致：

```json
{
  "device_id": "LAB_SENSOR_01",
  "telemetry_schema": {
    "environment.temperature": {
      "label": "环境温度",
      "unit": "℃",
      "semantic": "temperature"
    },
    "environment.humidity": {
      "label": "相对湿度",
      "unit": "%RH",
      "semantic": "humidity"
    },
    "channels[0]": {
      "label": "振动 X",
      "unit": "mm/s",
      "semantic": "vibration"
    }
  },
  "environment": {
    "temperature": 25.6,
    "humidity": 58.2
  },
  "channels": [1.28, 0.87, 0.61],
  "status": "normal"
}
```

字段显示规则如下：

- `label`：页面字段名称；未提供时显示字段路径；
- `unit`：单位，例如 `℃`、`kPa`、`V`、`%RH`；
- `semantic`：业务语义，例如 `temperature`、`pressure`、`voltage`；
- 最新一帧中携带的 `telemetry_schema` 会作为该数据源当前的展示定义；建议首次上报、字段新增和字段定义调整时都携带它。

## 6. 使用节点密钥上传（快速联调）

### 6.1 准备文件

新建 `telemetry.json`，将 `LAB_SENSOR_01` 替换为已注册的节点 ID：

```json
{
  "device_id": "LAB_SENSOR_01",
  "telemetry_schema": {
    "environment.temperature": {"label": "环境温度", "unit": "℃", "semantic": "temperature"},
    "environment.humidity": {"label": "相对湿度", "unit": "%RH", "semantic": "humidity"},
    "power.voltage": {"label": "供电电压", "unit": "V", "semantic": "voltage"}
  },
  "environment": {
    "temperature": 25.6,
    "humidity": 58.2
  },
  "power": {
    "voltage": 12.1
  },
  "status": "normal"
}
```

### 6.2 Windows PowerShell 上传

```powershell
$base = "http://8.163.62.41"
$nodeKey = "<注册节点后复制的 node_key>"

curl.exe -X POST "$base/api/upload" `
  -H "Content-Type: application/json" `
  -H "X-WindSight-Node-Key: $nodeKey" `
  --data-binary "@.\telemetry.json"
```

成功响应示例：

```json
{
  "status": "success",
  "record_id": 42,
  "telemetry_id": 42,
  "source": {"field": "device_id", "id": "LAB_SENSOR_01"},
  "metric_count": 3,
  "auth": {"version": "legacy-node-key"},
  "device_config": {"upload_interval_seconds": 60}
}
```

`metric_count` 是本帧识别出的数值字段数量。若它为 `0`，说明数据已保存，但当前 JSON 内没有可绘图的数值字段。

## 7. 使用 HMAC-SHA256 上传（终端推荐）

### 7.1 HMAC 请求头

| 请求头 | 固定值或来源 |
| --- | --- |
| `X-WindSight-Signature-Version` | `v1` |
| `X-WindSight-Algorithm` | `HMAC-SHA256` |
| `X-WindSight-Device-Id` | 已注册节点 ID，例如 `LAB_SENSOR_01` |
| `X-WindSight-Key-Id` | 注册节点时生成的 `key_id` |
| `X-WindSight-Timestamp` | Unix 秒时间戳或 ISO UTC 时间 |
| `X-WindSight-Nonce` | 每次请求都不同的随机字符串，最长 128 字符 |
| `X-WindSight-Body-SHA256` | 原始请求体字节的 SHA-256 十六进制摘要 |
| `X-WindSight-Signature` | HMAC-SHA256 签名十六进制值；可选前缀 `sha256=` |

服务端默认只接受与当前时间相差不超过 **300 秒** 的请求；同一 `key_id` 下的 `nonce` 不可重放。

### 7.2 签名原文

严格按以下 9 行拼接，不要增加空行：

```text
WIND-SIGHT-HMAC-SHA256
v1
POST
/api/upload
DEVICE_ID
KEY_ID
TIMESTAMP
NONCE
BODY_SHA256
```

签名计算：

```text
HMAC-SHA256(secret, canonical_string)
```

其中 `DEVICE_ID` 必须与 JSON 中最终选中的来源 ID 相同。

### 7.3 Python 终端示例

安装依赖：

```bash
python -m pip install requests
```

保存为 `upload_hmac.py`，填入自己的 `KEY_ID` 与 `SECRET`：

```python
import hashlib
import hmac
import json
import secrets
import time

import requests

BASE_URL = "http://8.163.62.41"
NODE_ID = "LAB_SENSOR_01"
KEY_ID = "<注册时生成的 key_id>"
SECRET = "<注册时生成的 secret>"

payload = {
    "device_id": NODE_ID,
    "telemetry_schema": {
        "environment.temperature": {"label": "环境温度", "unit": "℃", "semantic": "temperature"},
        "environment.humidity": {"label": "相对湿度", "unit": "%RH", "semantic": "humidity"},
        "power.voltage": {"label": "供电电压", "unit": "V", "semantic": "voltage"},
    },
    "environment": {"temperature": 25.6, "humidity": 58.2},
    "power": {"voltage": 12.1},
    "status": "normal",
}

# body、body_sha256 和实际发送内容必须完全一致。
body = json.dumps(payload, ensure_ascii=False, separators=(",", ":")).encode("utf-8")
timestamp = str(int(time.time()))
nonce = secrets.token_hex(16)
body_sha256 = hashlib.sha256(body).hexdigest()
canonical = "\n".join([
    "WIND-SIGHT-HMAC-SHA256",
    "v1",
    "POST",
    "/api/upload",
    NODE_ID,
    KEY_ID,
    timestamp,
    nonce,
    body_sha256,
])
signature = hmac.new(SECRET.encode("utf-8"), canonical.encode("utf-8"), hashlib.sha256).hexdigest()

headers = {
    "Content-Type": "application/json",
    "X-WindSight-Signature-Version": "v1",
    "X-WindSight-Algorithm": "HMAC-SHA256",
    "X-WindSight-Device-Id": NODE_ID,
    "X-WindSight-Key-Id": KEY_ID,
    "X-WindSight-Timestamp": timestamp,
    "X-WindSight-Nonce": nonce,
    "X-WindSight-Body-SHA256": body_sha256,
    "X-WindSight-Signature": signature,
}

response = requests.post(f"{BASE_URL}/api/upload", data=body, headers=headers, timeout=15)
print(response.status_code)
print(response.json())
response.raise_for_status()
```

运行：

```bash
python upload_hmac.py
```

> 不要把 `SECRET` 放在公开代码、串口日志、前端页面或 Git 仓库中。建议通过设备安全存储、环境变量或专用配置分区保存。

## 8. 实时数据台与历史回放

### 8.1 查看实时曲线

1. 打开 **实时数据台**。
2. 在“选择数据源”下拉框选择刚刚上报的节点。
3. 在“选择数值字段”勾选需要查看的字段。
4. 查看“数值摘要”“字段曲线”“原始报文”和“最近记录”。

实时页面保持四宫格展示方式：可勾选任意数量的字段，但当前实时曲线区域最多并列显示前 **4** 项；取消或重新勾选字段即可切换显示项。

### 8.2 查看历史曲线

1. 打开 **历史回放**。
2. 选择数据源和一个或多个数值字段。
3. 可设置开始时间、结束时间和最多记录数，或使用“近 5 分钟”“近 30 分钟”等快捷范围。
4. 点击 **查询历史**。
5. 在曲线区查看趋势；点击记录列表中的某一帧，可在右侧查看该时刻完整 JSON。

## 9. 日常维护操作

### 调整上传周期

在 **我的数据源** 选择节点，在“上传周期”中填写 5～86400 秒并保存。新的周期会在下一次上传响应的 `device_config.upload_interval_seconds` 中下发给终端。

### 修改显示名称

在 **我的数据源** 选择节点，点击“编辑名称”。此操作只改变页面名称，不改变节点 ID，不影响终端上传。

### 重置凭据

在节点详情点击“重置签名凭证”。将新配置同步到终端后再继续上报；可选择给旧 HMAC 凭据保留 24 小时过渡时间。

### 节点在线状态

数据源在配置的离线判定时间内持续成功上报，即显示在线。长期未上报会显示离线；这不会删除历史数据。

## 10. 常见问题

| 现象或错误码 | 原因 | 处理方法 |
| --- | --- | --- |
| `telemetry_invalid` | 请求体不是对象，或缺少 `node_id`、`device_id`、`source_id` | 发送顶层 JSON 对象，并保留一个合法来源标识。 |
| `source_identifier_invalid` | 节点 ID 不符合 3～64 位、`A-Z 0-9 _ -` 规则 | 使用已注册的规范节点 ID。 |
| `node_not_registered` | 来源 ID 尚未注册或节点已停用 | 先在“我的数据源”注册对应节点。 |
| `legacy_node_key_invalid` | `node_key` 缺失、错误或与节点不匹配 | 复制当前节点的正确 `node_key`。 |
| `missing_hmac_headers` | 发送了部分 HMAC 头，但头不完整 | 发送全部 8 个 HMAC 头，或删除所有 HMAC 头后改用 `node_key`。 |
| `timestamp_out_of_window` | 终端时间与服务器相差超过默认 300 秒 | 校准终端时钟或使用 NTP。 |
| `body_sha256_mismatch` / `signature_mismatch` | 签名的字节与实际发送 body 不一致 | 对同一份原始 UTF-8 bytes 计算摘要、签名并发送。 |
| `nonce_replay` | 同一个 HMAC `nonce` 被重复使用 | 每次请求生成新的随机 nonce。 |
| 上传成功但没有曲线 | 没有有限数值字段，或未在页面勾选字段 | 检查 JSON 数值字段，刷新页面后选择对应字段。 |
| 数据源没有出现在下拉框 | 该节点尚未成功上传一帧通用 JSON | 确认响应为 `status: success`，然后刷新数据源列表。 |
| 单位或中文名称不对 | 新帧的 `telemetry_schema` 未带上，或路径写错 | 使用与展开字段路径完全一致的 schema 键并重新上传。 |
